# ADR-002 — 为什么样本是 45 只「存活者」，以及这值多少个百分点

## 决定

样本数据 = 45 只美股大盘，全部满足「2013 年至今有完整价格 + 完整季度财报 + 今天仍上市」。
数据从参考实现的缓存冻结（`tools/build_sample.py`），随仓库提交，`make run` 完全离线可复现。

## 为什么不直接用全市场 / 含退市股的面板

1. **可复现优先**。一个 7 天的工作坊里，学生最常"炸掉"的地方是数据（权限、限流、改名、
   复权基准）。冻结数据把这类失败推迟到 L3，而不是打断 L0。
2. **成本**。免费源里没有一个同时提供「无偏宇宙 + 历史财报」；自建退市面板要
   500+ 次抓取与清洗（参考实现用了 Tiingo + SEC XBRL 才凑出 165 只齐全的）。
3. **诚实可控**。有偏但**明说**，好过无偏但不可复现——后者学生会以为结论是稳的。

## 代价（参考实现已量化）

| 口径 | CAGR | 超额 |
|---|---|---|
| 508 只现存成分（有存活者偏差） | 13.11% | −0.75pp |
| 673 只含退市股（修正后） | 9.89% | **−3.69pp** |

即：**存活者偏差单独贡献约 +3.2pp 年化**。所以本 repo 的 14.69% / +1.03pp
应读作**上界**；真实期望大概率更低，甚至为负。

另有一层：45 只都是"知名大盘"，动量因子在这种面板上天然占便宜
（见 `graveyard/h001_momentum_weight/`：移除动量掉 3.38pp）。

## 什么时候必须换掉样本

- 想验证**任何**因子结论（这是第一优先级）。
- 组合规模上来后要评估容量。
- 学生要做 L3 的"上云"练习——真实管线的第一件事就是把"宇宙怎么定义"写清楚。

## 怎么换

`data/sample/` 有四个 CSV，接口就这四个：

```
prices.csv        ticker, date, close, volume
fundamentals.csv  ticker, period_end, revenue_ttm, net_income_ttm, eps_ttm,
                  gross_profit_ttm, cfo_ttm, fcf_ttm, total_assets,
                  total_liabilities, equity, period
universe.csv      ticker, name, sector
```

替换后先跑 `make validate`：数据契约会先拦你一遍（重复、缺口、未来数据）。
如果你想复现「含退市股」的无偏面板，参考实现里的做法是
**Tiingo 日 K + SEC XBRL 财报 + SEC 股数×收盘价市值**，全部免费源。
